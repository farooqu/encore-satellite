# Executed protocol proof

The shared Go core passed a real local Home Assistant Assist stack with virtual
audio and deterministic speech fixtures. This verifies protocol behavior on the
pinned development baseline, not hardware support or recognition quality.

## Baseline and commands

The starting repository contained only the introductory README. The lab uses
Home Assistant `2026.12.0.dev0` at
`1395798e2338bd46ee522539f7281b336c44e3b8` and aioesphomeapi 46.30.0.
No HA session/protocol source was patched. See [lab setup](README.md).

Executed on Linux x86-64 in the Encore orb:

- `.agents/setup`: installed/resolved the pinned environment; warm rerun succeeded.
- `make check`: dependency boundaries (including test imports), `go vet ./...`
  and `go test -race ./...` passed.
- `go test -race -count=30 ./core/... ./backends/...`: passed.
- `go build -o .amp/in/orb-backup/encore-lab ./cmd/encore-lab`: passed.
- `make lab-test`: expanded real-stack suite passed, then passed again after the
  deliberate drain fault described below was removed.

## Real HA and deterministic fixtures

`lab/test_assist.py` exercises real multicast discovery, HA onboarding/auth,
ESPHome configuration, encrypted connections, capability negotiation, Assist
pipeline, HA conversation/intents and TTS transport. STT consumes/hashes supplied
PCM and returns a fixed command; TTS synthesizes a mathematical tone. A bounded,
clocked virtual sink records consumption independently of receipt.

- Incorrect configuration key and direct wrong-key connection were denied;
  correct key paired. Empty entity discovery completed. Advertised capabilities
  were exactly 7. Unsupported and competing subscribers did not displace HA.
- Full turn: HA received 16,000 PCM bytes with SHA-256
  `62bf710411f85b3d39a0d132011ada5af62892e87c6b32f986dd3da3f044223b`;
  HA's actual intent turned on `input_boolean.encore_lamp`; the sink consumed
  16,000 samples and emitted one drain completion. Output bytes were checked
  against an independently generated waveform, not only a nonempty response.
- Held short TTS: 3,200 samples received, zero played, no completion; releasing
  the sink consumed 3,200 samples and produced exactly one completion.
- Cancellation during capture, delayed recognition and playback cleared the
  local queue, suppressed late text/audio and false drain, and recovered through
  encrypted reconnect. Mute revoked transport and rejected capture/start until
  unmute and reconnect.
- Real STT failure emitted `stt-stream-failed`. This HA build logs fixture TTS
  failure but emits a normal empty stream/end without protocol ERROR; Encore
  made no playback claim and did not invent an unavailable backend error.
- Backend switching flushed blocked Assist output without completion, attached
  a native Incubator **peer fixture**, revoked its stale transport, then recovered
  the real HA connection. A full turn passed after errors/cancellation and after
  HA integration reload.
- Separate encrypted peer fixtures injected odd/oversized PCM, a UDP-only start
  response and a rejected start. Each revoked its connection safely. These
  malformed messages were not generated by real HA.

Real HA runs exposed two important compatibility issues: API_AUDIO subscription
uses bit `1 << 2`, and an old cancelled HA TTS task can deliver its final stream
event on a new connection. The adapter now uses the verified subscription bit;
the core ignores unsolicited output/end without an active local Assist stream.

## The proof rejects a broken implementation

Temporarily replaced `e.player.Drain(ctx)` with `nil`, rebuilt/restarted Encore
through the unchanged `make lab-test`, and captured exit 2. The suite failed at
the full-turn assertion that all expected samples had actually played with an
empty sink queue. Restoring the real drain and rerunning the same suite passed,
including the stronger held-sink case. The deliberate mutation is not included.

## Native Incubator is contract-tested, not upstream-validated

Race-enabled TCP tests cover protocol-2 framing/hello, original pre-roll and
candidate scores, continuing capture during upstream processing, upstream
`answered_elsewhere`, zero-pre-roll follow-up, held playback drain, cancellation,
late output, reconnect/backend selection, competing peers and malformed frames.
They use explicit peer fixtures, not the full Voice Incubator service.

An exploratory upstream startup reached the missing English shared
CTC/transducer model check after installing dependencies, fetching wake assets
and building Kaldi. It did not reach a running assistant. Resolving upstream
model layout/download prerequisites and exercising actual wake verification,
recognition, election and HA integration remain required.

## Explicitly unproven

No physical capture/playback, acoustic quality, AEC, EQ, wake model, hardware mute,
Dot/Android runtime, dashboard host, installer, updater or performance claim.
No Assist cross-device quality arbitration or experimental WAKE_WORD_AUDIO
verification. No partial captions inferred when upstream supplies none. The
lab remains running under supervised services; authentication and Noise secrets
stay outside Git. New Encore licensing remains unselected; required included
MIT notices are retained separately from design acknowledgements.
